# UI tweaks: click-safe editing, Spotlight removal, stable focus border

## Goal

Make task text editable only via an explicit ✎ button, delete Spotlight mode entirely, and stop the 1px layout jump when a task row becomes active.

## Architecture / proposed approach

Three ordered commits on a new branch `feat/ui-tweaks`, each gated by `pnpm compile && pnpm build` plus a new CDP behavior suite (`tweaks-test.mjs`, written FIRST so every check starts RED). Tweak 1 uses the textarea's native `readonly` property: rows render read-only, a ✎ row button unlocks + focuses, `blur` re-locks, and tasks created by explicit actions (Enter, ＋, + Add task) start unlocked. Tweak 2 is a pure excision (tsc catches leftovers). Tweak 3 gives every row a 1px transparent border so the active green border changes color, not geometry.

Design decisions (settled, do not re-litigate):
- A plain click on task text still FOCUSES the row (selects it for the Timer flow and the highlight) but cannot change text. Only ✎ or creating a task enters edit mode.
- Keyboard mutation shortcuts (Enter/Tab/Backspace) are gated to edit mode — a stray click + stray keypress must not mutate the tree.
- Every `renderTree(focusId)` call follows an explicit user action (create/indent/outdent/delete-redirect), so the focused textarea is unlocked there. Side effect: deleting a task puts its previous sibling in edit mode. Accepted — it matches "focus after explicit action = editable".
- The orphaned `spotlight` key in existing users' `chrome.storage.local` is left in place, ignored. No migration (YAGNI).
- The `#tree [data-id] { transition: opacity 120ms ease; }` rule STAYS — the fade-on-leave feature uses it. Only `.row-dim` and the Spotlight comment go.

## Risks / tradeoffs / open questions

- **Read-only caret**: a focused read-only textarea still shows a caret and allows text selection. Accepted — selection is useful (copying task text), and the ✎ affordance plus hover border signal editability.
- **Blur re-lock side effects**: clicking ⤢ expand, the checkbox, or a toolbar button blurs the textarea and re-locks it; continuing to edit needs another ✎ click. Accepted for consistency (checkbox clicks re-render the tree anyway).
- **Delete-redirect unlocks the neighbor** (see design decisions). Accepted; matches pre-tweak focus behavior.
- **Row height grows 2px globally** (every row now has a real 1px border). Uniform, so no relative shift; vertical rhythm changes imperceptibly.
- **Orphaned `spotlight` storage key** remains in existing profiles, ignored forever. Harmless; no cleanup code (YAGNI).
- **PiP**: the same DOM node moves into the PiP window; all listeners are attached to the nodes themselves, so ✎/blur/readonly travel with them. The regression `pip-test.mjs` covers float/dock; the fade suite covers PiP interaction.
- Open question (do NOT block on it): whether double-click should also enter edit mode. Out of scope — the user asked for a button only.
